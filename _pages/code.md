The repository that serves this site also carries the pipeline itself. Nothing on these pages is
transcribed by hand. Each figure and each table is generated by a script in this repository that reads
the result files in this repository, so a number cannot appear on the site unless it exists in a
committed artefact first. If you want to check a claim, the shortest path is to open the corresponding
JSON file rather than to trust the prose around it.

## What is here

Raw sequencing data and trained neural weights are not versioned in either repository. They are
reconstructed from the manifests, which is why the manifests carry hashes rather than merely paths.

## Reproducing a published number

Install the package, fetch the open corpora, and verify that what arrived matches what was recorded.

```
pip install -e .
pdac fetch-data --all-open
pdac verify-data
```

Verification recomputes the SHA-256 of every file against its manifest entry and fails loudly on a
mismatch, so a silently corrupted or silently updated download cannot propagate into a result. From
there each experiment is a single script. The four scale-up runs behind the Results page are

```
python pipeline/grna_cnn_kim_retrain.py
python pipeline/promoter_scaleup.py
python pipeline/enhancer_maxdata.py
python pipeline/promoter_gan_scaleup.py
```

Each writes a JSON file into `results/` and, where a model is deployed, refreshes the manifest and the
frozen prediction fixture together. The fixture check is what makes deployment auditable. It stores a
small batch of held-out inputs alongside the predictions the deployed weights produced for them, so a
later run can prove that the weights on disk are the weights that earned the reported metric.

## Relationship between the two repositories

The pipeline is developed in
[pdac-chromatin-circuit](https://github.com/MurariAmbati/pdac-chromatin-circuit), which remains
authoritative. This repository holds a mirror of its tracked files so that the site and the code it
describes can be read in one place, and so that a reader who clones the site repository can rerun the
analyses without a second checkout. The mirror is produced by a script rather than by hand.

```
python scripts/sync_from_pipeline.py
```

That script records the source commit in `PIPELINE_SOURCE.json` at the repository root. Divergence
between the two copies is therefore visible rather than silent, because the recorded commit either
matches the upstream head or it does not.

## Rebuilding the site

```
python scripts/make_figures.py
python scripts/build_pages.py
```

The first reads `results/` and writes `images/`. The second reads `docs/`, the report files at the
repository root, and `results/`, then writes the generated pages under `_pages/`, including the
Evaluation, Figures and [Circuits]({{ site.baseurl }}/circuits/) pages. Nothing in those three is
written by hand, so correcting a number means correcting the result file it came from.

## Tests

```
pytest -q
```

The suite covers the deterministic parts of the pipeline, the provenance and fixture machinery, the
statistical helpers, and the abstention paths that produce a certified negative when evidence is
insufficient. It does not retrain models, so it runs in about a minute and does not require a GPU.
